## The goal

In Rebecca's day, a diary, logbook or letter she finds should open the way
RE1's files do: full-screen pages she turns through, kept afterwards in the
FILE tab of the status screen. Today each one is a few lines of message text
at the bottom of the screen. The owner called that "not correct" and wants
real files.

Done means:

1. Each document below opens as RE1 file pages in the game, in her mode
   (`--mode REB`), and stays readable afterwards from the FILE tab.
2. The page art is made by our tools from our own text, never copied from the
   game's files.
3. A harness test picks a file up in its room, reads it and finds it in the
   FILE tab, and saves a screenshot as proof.
4. Chris's and Jill's games are unchanged: everything of hers comes from the
   REB overlay or is behind her mode.

## What RE1 already has

These facts were checked against the code on 2026-10-14:

- The FILE tab is `menu_tab_file` (`src/game/MainMenu.cpp:2267`), driven by
  `menu_file_state_machine`. State 0 is the book selector and state 1 is
  reading. Reading runs `file_reader_advance` (around `:4879`) into
  `pickup_screen_render` (around `:4255`). `menu_update_status_screen`
  (around `:4184`) shows a file at the moment it is picked up.
- The page art lives in `item_m2/filem_l0.pix` to `filem_z0.pix` and
  `filem_00.pix` (table at `MainMenu.cpp:3795`), unpacked by
  `pickup_unpack_list` (around `:4081`). The book covers are
  `item_m2/file000.tim` and `file001.tim`.
- A file is an item: its file index is `itemId - 0x5F`. There are 16 slots,
  and the collected flag is room flag `0x82 + index` (`src/game/BioCard.h:220`).
  Her day has ten documents, so they fit.
- Room scripts give items with `cmd_got_item` (opcode 0x2D) and the item
  pickup room action. No separate "read file" opcode was found. See
  `docs/SCD_COMMAND_OPCODES.md` and `src/game/CmdFunctions.cpp:629`.
- The REB overlay is searched before the base tree (`src/system/AssetPath.cpp`).
  `item_m2/filem_` is on the list of prefixes that fall back to the base files
  silently, so an overlay copy of a page file wins when it exists.
- Her rooms' things to examine come from `room.check(zone, text)` in
  `tools/rebecca/blender/kit.py`. They land in `renders/room.json`, and
  `tools/rebecca/day/scripts.ts` turns each one into
  `aot_set(..., SCE_MESSAGE, ...)` in the room's `room.c`, with its text in
  `room.msg.txt`.

These are leads, not a design. Confirm each one before you build on it:
- the page format inside a `.pix`;
- how a page count is stored;
- where file names and descriptions come from;
- how the FILE tab lists a file.

The decomp's rule from `AGENTS.md` applies: if you need Ghidra and its MCP
server is not available, ask the owner. Don't guess the original code.

## A suggested shape

Change it if the code says otherwise.

1. `docs/REBECCA_FILES.md` explains how RE1's files work, with addresses.
2. `tools/rebecca/files/documents.ts` holds the ten documents: each one's
   text, pages, paper style, file slot, and the room and zone that give it.
3. `tools/rebecca/files/pages.ts` renders text onto paper and writes the
   page containers in the game's format. A test proves the round trip: write
   pages, then decode them with the same logic the game uses.
4. In her mode, her file slots use her names and pages. The pages come from
   the REB overlay. The names come from a table chosen by mode, or from the
   overlay if the engine already loads them from data.
5. `tools/rebecca/day/scripts.ts` emits a file pickup instead of
   `SCE_MESSAGE` for a check that `documents.ts` names. The cabin's logbook
   is hand-written in `lookout/room.c`, so change it by hand.
6. `tools/harness/tests/files.ts` boots into a room, walks to the document,
   presses action, checks the file opened and is listed in the FILE tab, and
   saves screenshots.
